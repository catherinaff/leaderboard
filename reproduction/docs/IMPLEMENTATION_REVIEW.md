# Implementation review — 2026-11-19

This review concerns the code paths and completed runs used by the HAR leaderboard. It does not certify a matched original-paper experimental protocol. Unchanged author components, paper ports, task adaptations, unrun interfaces and paper-only entries are distinguished below.

## Source and operation checks

- 25/25 critical upstream files were freshly fetched from their fixed official commits and matched SHA256; 0 mismatches and 0 unavailable files.
- Original acquisition manifests additionally checked 1099 source-file hashes across 16 recorded source trees, with 0 mismatches. Old manifests that listed filenames without hashes are not counted as hash checks; their used files are covered by the fresh critical-file comparison.
- Numeric regressions checked peephole-LSTM forward/input gradients, Lasagne RMSprop epsilon placement, TF1 reset-before GRU arithmetic, gradient reversal and explicit oneHAR loss/selection components. These checks do not imply that omitted oneHAR objectives were used in its supervised adapter.
- RobustHAR tests directly transcribed the selected fusion equations and checked encoder freezing and finite gradients. The paper ambiguities and chosen interpretations remain in ROBUSTHAR_AUDIT.md.
- Author HART, MobileHART and iSPL models passed fresh CPU forward/backward checks. Source model.py bytes match their recorded commits.
- OneLLM SDPA matched explicit attention including cached unequal query/key lengths; native input mapping and SensorLLM original notebook trend/summary functions were checked. Disabled API routes and real SDK serialization were tested with the network blocked: zero paid calls.

Evidence: [official sources](../evidence/official_source_comparison.json), [recorded source trees](../evidence/upstream_source_inventory.json), [runtime checks](../evidence/runtime_review.json), [executed source bundles](../evidence/executed_source_bundles.json).

## Protocol and reproducibility findings

1. The shared data splits are fixed, but native sensor subsets, external pretraining and supervision differ. Reusing an upstream architecture does not reproduce the original paper split, label budget, optimizer schedule or score. The main display remains a starred reference ranking.
2. oneHAR is intentionally a per-dataset supervised CDNet adapter. Its three-loss joint-training and LLM synthesis workflow is not implemented by this experiment. TimeLLM adds a new classification task; SensorLLM substitutes independent MHEALTH alignment. These are labelled adaptations rather than exact reproductions.
3. The released IMU2CLIP tensor shapes/keys match, but a public community checkpoint is not evidence of original pretraining membership. UniTS and other pretrained backbones similarly retain their published asset provenance rather than a clean from-scratch claim.
4. The actual PAMAP validation selector in the shared runners is Weighted F1, while the main average is Accuracy. RealWorld validates on Macro F1. SensorLLM uses its own Accuracy selector except RealWorld Macro F1. These differences are preserved in training_recipes.json.
5. Epoch budgets are caps. Actual early-stopped epochs and model-specific pretraining stages are recorded separately. The original acquisition scripts are historical; fresh reproduction should use fixed source/asset manifests and the portable launchers.
6. Historical calibration/retired scripts are preserved for inspection and excluded from current measured rankings. Smoke or mock outputs cannot become a measured result; all admitted seed sets cover every required test subject.

## Files and verification boundaries

The readable runners/adapters are under experiments/. Exact executed authored snapshots are content-addressed under evidence/executed_source_objects/. Original third-party TensorFlow models and the HART UCI loader are referenced by SHA and fetched from their original repositories, rather than republished as our code. Path-only portability edits are listed in evidence/portability_changes.json. Model arithmetic was not changed on the active compute server by this packaging/review task.

Runtime/operation tests support the individual claims above. They do not establish end-to-end numerical equivalence for every framework port, recover undocumented original training data, or turn an adapter into a full-paper reproduction.
